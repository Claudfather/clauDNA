# P1 — publish two-plane router

Part of the Claudron-integration epic (`00_OVERVIEW.md`). Size: **L**. Ungated (no
Claudron dependency). Fork gate: **F3 locked before merge** (this phase implements its
outcome).

## Summary

Discharge the deferral at `output-guide.md:19`: make `/claudna:publish` the single
router over both doc planes. This is not a prose swap — the panel showed the mechanism
needs building: publish is a single-file adapter today, while the audit engine writes
multi-file session directories whose `00_` masters would fail publish's own skeleton
hard gate. So the `docs` adapter ships with **single-doc and family modes** and a
master-doc validation policy, the `disk` adapter is renamed `vault` with a scoped
one-release alias, and the plane doctrine (with the four-way which-door table) lands in
documentation-standard.

## Evidence

- `skills/_shared/output-guide.md:19` — "Reconciling the two is its own change."
- **The mechanism gap (panel blocker):** `skills/publish/SKILL.md:56-58` — Step 1b hard
  gate rejects any `plan|audit|review` doc lacking `## Implementation Plan`/`### Steps`;
  audit-engine session output is a directory of `00_` master (inventory/dependency
  matrix — no such skeleton) + `NN_` phase docs (`skills/audit/tech-debt/tech-debt.md:150-175`).
  Routing that family through today's publish fails validation.
- **The stale-prose contradiction:** `skills/forge/SKILL.md:22,:206` already describes
  `--output docs` as routing through publish ("disk → a PR-reviewable plan directory")
  while publish's disk adapter targets `shared/planning/active/`
  (`skills/publish/SKILL.md:69-76`). P1 makes forge's description true and then fixes
  the description's residual wording.
- **Author-skill sweep is bigger than it looks:** grep shows ~8 skills reference
  `documentation/planning` write paths (audit lenses via `audit-lens-contract`,
  product-enhance, product-vision, forge, implement-plan's archive step, session
  handoff's scan) — each write path gets audited, not one-line-edited blind.
- Alias precedent: hard renames are house style for **picker entries** (#165 F4 "no
  stub interlude"), but adapter *flag values* are API surface scripts may embed — and
  the repo's one prior stranding (0.2.0 consumers, cited by SETUP_GUIDE §4.3.1's pin
  recipe) argues for a grace window on flags. The F4 doctrine is hereby scoped to
  picker entries; this alias is not a stub.

## Implementation Plan

### Dependencies
None external. Fork F3 locked.

### Blocks
P3 (doctrine + which-door table), P4's `--to vault` engine upgrade, #116/#159's
remaining work.

### Steps

1. **`--to docs` adapter, two modes.**
   - *Single doc:* `publish <file> --to docs --dir <path-under-documentation/>` —
     validates the dir is under `documentation/`, writes, no INDEX step (the docs plane
     is git/PR-discovered).
   - *Family:* `publish <dir> --to docs` — a per-doc loop over `00_*` + `NN_*.md`
     (mirrors forge F7's family-publish): **phase docs validate against the full §4.1
     skeleton; the `00_` master validates for presence only** (frontmatter + non-trivial
     body + leading heading — the knowledge-tier check). Rationale recorded in the
     adapter: the Step 1b hard gate exists for implement-plan readiness, which is a
     property of phases, not inventories.
2. **Rename `disk` → `vault`;** keep `disk` as a deprecated alias for exactly one
   release (warn once per invocation), with the doctrine-scoping note from Evidence in
   the CHANGELOG entry. Adapter behavior otherwise unchanged in this phase (raw-tree
   write + `/claudna:index`); P4 upgrades it to prefer the engine.
3. **Plane-fit advisory:** `plan|audit|review` → `--to vault` and `knowledge|runbook` →
   `--to docs` emit a one-line "unusual plane for this type" note. Advisory only, never
   a block (fleet workflows legitimately share plans vault-side). The epic Risks table
   says "advises," matching this.
4. **Retire the §1 deferral in `output-guide.md`:** replace the deferred-unification
   paragraph with the two-plane routing table; update §7's reference snippets.
5. **Author-skill sweep (grep-derived, not hand-listed):** for each skill writing under
   `documentation/`, repoint its default docs output at `publish --to docs --dir <its
   category dir>` (single or family mode as its output shape requires), and fix stale
   prose — including forge's `--output docs` description. The sweep list is generated by
   grep at implementation time and recorded in the PR body.
6. **`skills/_shared/documentation-standard.md` — plane doctrine:** the two-plane table
   (what lives where, why), the vault layout pointer (SCHEMA.md directory taxonomy),
   the raw-tree-fallback note, and the **which-door table**: `/claudron write` =
   deliberate save · `/learn` = external ingestion · `/reflect` = session distillation ·
   `publish --to vault` = finished-doc routing.

## What NOT To Do

- Don't flip any *default* destination — this phase adds routing, not policy churn.
- Don't hard-block cross-plane publishes — advisory only.
- Don't make `00_` masters skeleton-compliant by stuffing fake `### Steps` into
  inventories — the exemption is the design, not a workaround.
- Don't touch INDEX.md mechanics for the docs plane.
